# 機能仕様書: Enable tests on all branches (GitHub Actions)

**機能ブランチ**: `001-test-all-branches`  
**作成日**: 2026-02-15  
**ステータス**: ドラフト  
**入力**: ユーザー記述: "Github actionで、master以外のブランチもテストは実行したい"

## ユーザーシナリオとテスト *(必須)*

### ユーザーストーリー 1 - 全ブランチでのCI実行 (優先度: P1)

開発者が任意の機能ブランチ（例: `feature/add-login`）にプッシュした際、GitHub ActionsのCIパイプライン（テストジョブ）が自動的に実行される。これにより、マージ前に回帰テストや品質チェックが可能になる。デプロイジョブは実行されない。

**この優先順位の理由**: 開発サイクルを通して継続的にコード品質を監視するため、最も重要かつ基本となる機能。

**独立したテスト**:
- 新しいブランチを作成し、空のコミットをプッシュすることで、CIがトリガーされるか確認可能。

**受入シナリオ**:

1. **前提** 開発者が `master` 以外のブランチを作成している、**もし** そのブランチに変更をプッシュする、**ならば** GitHub Actions の `build` ジョブが開始される。
2. **前提** `build` ジョブが完了する、**もし** ブランチが `master` ではない、**ならば** `deploy` ジョブはスキップされる（実行されない）。

---

### ユーザーストーリー 2 - Masterブランチでのデプロイフロー (優先度: P1)

開発者が `master` ブランチに変更をプッシュ（またはマージ）した際、CIパイプライン（テストジョブ）が実行され、成功した後にデプロイジョブが実行される。

**この優先順位の理由**: 本番環境へのデプロイを維持するために必須。既存の機能を壊さないことの保証。

**独立したテスト**:
- `master` ブランチへのプッシュでデプロイまで行われることにより確認可能。

**受入シナリオ**:

1. **前提** 開発者が `master` ブランチに変更をプッシュする、**もし** `build` ジョブが成功する、**ならば** `deploy` ジョブが開始され、Fly.ioへのデプロイが行われる。

## 機能要件 *(必須)*

- **CIトリガーの拡大**: GitHub Actions のワークフロー（`deploy.yml`）は、`master` ブランチだけでなく、すべてのブランチへの `push` イベントでトリガーされなければならない。
- **ジョブ実行条件の制御**:
    - **Buildジョブ**: すべてのブランチでのプッシュ時に実行されること。
    - **Deployジョブ**: `master` ブランチへのプッシュ時のみ実行されること。他のブランチでは実行をスキップすること。
- **依存関係**: `deploy` ジョブは `build` ジョブの成功に依存し続けること（`needs: build`）。

## 成功基準 *(必須)*

1. 非masterブランチ（例: `feature/test`）へのプッシュ時に、GitHub Actions上で `build` ジョブが実行され、テスト結果が報告される。
2. 非masterブランチへのプッシュ時には、`deploy` ジョブが実行されない（またはスキップされる）。
3. `master` ブランチへのプッシュ時には、従来通り `build` ジョブ実行後に `deploy` ジョブが実行され、デプロイが完了する。

## 仮定 *(オプション)*

- プロジェクトは `master` ブランチを本番デプロイ用のブランチとして使用している。
- `deploy.yml` ファイルが唯一のCI/CD定義ファイルである。
